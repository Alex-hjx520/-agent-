# equipment-agent · 制冷设备流量选型系统使用手册

按【质量流量窗口】直接选型的完整系统：输入工况与制冷量 → 用 CoolProp 算需求质量流量
`m_req` → 对数据库全部类型候选按 `m = Kv·√Δp·√(1000·ρ)` 判定是否达标 → 输出达标型号与报告。

---

├── .env                    # 环境变量（DEEPSEEK_API_KEY / MYSQL_*）

## 2. 启动（只需两个服务）

```powershell
# ① 后端 8010（从项目根目录，保证 .env 相对路径生效）
.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8010

# ② 前端 5173
cd qian-duan
npm run dev
```

浏览器打开 http://127.0.0.1:5173 。

## 3. 使用流程（页面）

顶部「流量选型」页右上角切换两种输入：

**A. 表单填写**：设备类型(全部/某类)、制冷剂、冷凝温度、蒸发温度、过冷度、过热度、
允许压降(可空)、需求制冷量 → 开始选型 → 达标排行。

**B. 对话输入**：直接说话（如"R410A 制冷量 20kW"）。大模型澄清缺失参数并反问 →
补齐后自动选型 → 达标设备参数卡 → Markdown 报告（可「导出报告」）。

## 4. 后端接口

| 端点 | 说明 |
|---|---|
| `GET /health` | 健康检查 / Key 是否配置 |
| `POST /select/flow` | 表单式流量选型。Body：refrigerant/cond_temp/evap_temp/subcooling/superheat/delta_pressure/required_capacity/device_type(空=全部) |
| `POST /flow/chat` | 对话式选型。Body：message/history/params。返回 type=clarify(缺参反问)/done(需求+达标+报告)/error |
| `POST /parse-doc` | 上传 .docx/.txt/.md 解析为文本（工具） |

## 5. 选型模型与判定规则

- 需求侧（CoolProp，与设备无关）：
  - `Δh = h(蒸发压, te+SH) − h(过冷液, tc−SC)`（J/kg）
  - `m_req = 需求制冷量 × 3.6e6 / Δh`（kg/h）
  - `ρ = 阀前过冷液密度`（kg/m³）
- 设备侧：`m = Kv·√(Δp_bar)·√(1000·ρ)`（kg/h）
- 压降边界判定（字段有就给，给哪边判哪边）：
  - 有最大压降 → 只需 `m_req ≤ m_max`（m_max 在 `min(设备max, 允许压降)` 下）
  - 有最小压降 → 只需 `m_req ≥ m_min`
  - 两者都有 → `[m_min, m_max]` 窗口包含 m_req
  - **无 Kv 值 → 该型号跳过**（无法用流量公式）
- 候选=数据库全部类型表；排序：达标优先，达标内 **Kv 升序**（最小可行阀最紧凑）。

## 6. 数据库准备

1. 建表：执行 `数据库信息(开发结束后删除)/schema_all_tables.sql`
2. 导 CSV：把 `数据库信息(开发结束后删除)/` 下的 CSV 导入对应表
3. `.env` 配 MySQL 与 DeepSeek：
   ```
   DEEPSEEK_API_KEY=sk-xxx
   MYSQL_HOST=127.0.0.1 / MYSQL_PORT=3306 / MYSQL_USER=root / MYSQL_PASSWORD=... / MYSQL_DB=...
   ```
4. 说明：带 `kv_value` 且给 `min/max` 压降（至少其一）的型号才参与；四通等无 Kv 表自动跳过。

## 7. 常见问题

- **提示"数据库无候选"**：确认已建表导数据；表行需含 model 与 kv_value。
- **达标过多**：需求 20kW 常用阀都能覆盖；可调小允许压降或按设备类型过滤。
- **澄清不退出**：制冷剂、冷凝/蒸发、SC/SH、允许压降、需求制冷量 7 项需都给；可补"其余默认 0/5/0.5"。
- 端口占用：8010 被占换 8012 并同步改 `qian-duan/vite.config.js` 的 `BACKEND_PORT`。
